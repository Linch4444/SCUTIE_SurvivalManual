# 关于这本手册

> 一本由学生自发编写、面向华南理工大学工业工程（SCUT IE）学生的非官方生存指南。

## 这是什么

它涵盖了你从 IE 入学选择到毕业深造与就业的全阶段。它不是学校官方出版物，也不打算写成官方出版物，体例仿《上海交通大学学生生存手册》。

按三章结构组织，外加一份工具型附录：

1. **认清现状** — 你站在哪里
2. **基本方向** — 你往哪走
3. **存在主义** — 你怎么活
4. **附录** — 怎么查、怎么判断、路有哪些（可以当字典用）

## 关键前提（读之前必须知道）

- 华工工业工程隶属**工商管理学院**，不是机械学院
- 学位是**管理学学士**
- 学生大多在**大二申请二次选拔（"2+2"）、大三正式转入**，不是高考直招
- 面向对象：在读的、准备转入的、以及还在犹豫的华工工工学生

所以你会在站里看到一些"待补充"的标记。那不是偷懒，那是留白——留给知道答案的人。

## 免责声明

::: warning 请以官方为准
- 本手册为**学生自发编写**，非学校官方出版物。
- 涉及培养方案、学分、选课规则等，**以教务系统与学院最新通知为准**。
- 主观经验部分**仅代表个人观点**，不同届、不同老师的情况可能完全不同。
- 政策（尤其是考研、选调）每年都在变，**引用前请核实当年官方文件**。
:::

## 怎么贡献

这是全文最重要的一节。**这本手册能不能活过三届，取决于你看完这一节之后有没有动手。**

### 方式一：网页直接改（推荐，零基础）

不用装任何软件，会打字就行。

1. 打开你想改的那一页
2. 点页面底部的「在 GitHub 上编辑此页」链接，进入对应源文件
3. 直接改文字，在底部填写一句"改了什么、为什么"
4. 提交，等维护者合并

就这样。你不需要懂代码，也不需要懂 Git。没有写权限也没关系，GitHub 会自动引导你生成合并请求。

### 方式二：提 Issue 说问题

发现内容有错、链接失效、信息过时，但不想自己动手改？

直接提一个 Issue，写清楚：

- 哪一页、哪一段
- 哪里不对
- 正确的应该是什么（如果知道的话）

### 方式三：本地跑起来（适合想大改的人）

如果你想加一整节新内容，或者调整版式：

```bash
# 1. 安装依赖（需要 Node.js 20+，推荐 22 LTS）
npm install

# 2. 本地预览，改完自动刷新
npm run docs:dev

# 3. 构建成静态站点
npm run docs:build
```

内容都在 `docs/` 目录下，纯 Markdown：

```
docs/
├── index.md              # 首页
├── about.md              # 本页
├── ch1/  ch2/  ch3/      # 三章正文，一节一个文件
└── appendix/             # 附录 A / B / C / D
```

### 写作约定

- **一节一页**，文件放在对应章节目录下，命名格式 `序号-英文短名.md`
- 每页开头要有 `---` 包裹的 `title` 字段（只写小节名，**不要带编号**，编号由文件名自动生成）
- **侧边栏是自动生成的**：文件名前缀决定编号（`docs/ch2/03-internship.md` → 显示为「2.3 实习」），frontmatter 的 `title` 决定显示文字。新增页面只要按规范命名放进目录，**侧边栏自动出现，不需要改 `config.mts`**
- 页码编号会被自动处理，但**别跳号**（比如从 `02` 直接跳到 `04`），否则侧边栏会显示成 2.2、2.4
- 附录特殊：按文件名首字母 `a`/`b`/`c`/`d` 自动分到「附录 A/B/C/D」四个组，编号写在 `title` 里（因为存在 `A.3-A.4` 这类合并页）
- 风格参照现有内容：短句、直白、敢下判断，允许吐槽和网络语
- 引入新事实时，**在页脚注明来源和日期**
